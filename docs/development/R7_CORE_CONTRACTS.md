## 2. 当前任务契约

**任务来自当前操作者请求及仍适用的对话约束，不能由历史资料自动创建。**

- 问候、能力询问不启动旧研究；连接检查/诊断以完成所问检查并报告为终点，
  不顺带继续早先的分析或变更。
- 当前输入可收窄、替换、暂停旧目标；不是机械地只保留最后一句话。
  明确“继续”且唯一未完成目标可判定时可承接；目标已结束、取消或指代不清时先澄清。
  不引入逐工具确认系统。
- Research NextAction、Memory、Summary 和历史模型计划都是背景，不是新执行命令；
  保留其事实价值和来源，不靠删除历史、伪造任务事件或清空 reasoning 实现纠偏。
- DomainProfile/ResearchPhase 描述领域和**执行已请求研究时的方法**。默认 Mapping
  不应声明用户已经要求开始扫描；仍保留既有枚举、选择事件与 Turn 边界。
- `/resume` 重建状态，不自动重跑旧任务；`/stop` 使用现有取消边界，不承诺撤销副作用
  或结束所有后台进程。未知执行结果不能被任务切换改写为成功/取消。

所有者保持不变：CLI 输入与取消 → 现有 Turn/AgentLoop → PromptComposition/
ContextPlanner → immutable SamplingStepPlan → RequestAudit。
首先评估固定 Phase 措辞的最小修订；不预设新增任务分类模型、关键词路由、idle Phase、
TaskIntent 公共类型或第二份任务账本。Prompt 合规是模型行为指标，不是运行时硬保证。

## 3. 研究上下文契约

以下是语义区分，不是要求新增一个大结构体或持久化 Schema：

| 内容 | 来源及使用边界 |
|---|---|
| 当前目标/停止条件 | 操作者请求及仍适用的对话；不由 Phase 或旧 NextAction 推断新任务 |
| Project root | 既有 Project discovery/config 的事实；不等于分析目标或容器 cwd |
| Target/版本 | 显式输入、Research/TargetSnapshot 及适用范围；未知就标未知 |
| host/container/device 环境 | 对应环境的实际观察；宿主 OS 不能证明容器工具版本/参数 |
| cwd/输入/输出路径 | 现有工具参数与结果；明确属于哪个环境，不猜路径或创建目录 |
| 历史事实/当前观察 | 通过现有来源、适用目标、版本与新鲜度区分；Memory 不是新执行证据 |

通过既有 Context fragment/provenance 与审计表示这些区别，不复制另一份 Research authority。
缺少字段仅在当前任务确实需要时做有界观察；不是每轮自动全量环境探测。
`/tmp` 与 `/private/tmp` 可能是同一路径的规范化结果，须观察后判断，不能硬编码替换。
GNU/BSD/LLVM 参数兼容以实际执行位置和工具版本为准，不只按 OS 标签猜测。

要分别测量程序自身的 Project Snapshot 刷新与模型调用 `list_files/read_files`。
目前非 Git Project 的元数据指纹可能递归遍历；缓存命中不等于完全不遍历。
内部目录的默认展示优化应是可显式访问的发现/输出策略，不是权限隔离；不能直接将
Snapshot 的排除规则复制进通用文件工具，破坏显式读取和现有路径语义。

## 4. 最小能力扩展契约

当前工具是编译期 Registry + 通用进程工具。`tool_search` 只搜索已注册的 Deferred
工具，不搜索磁盘/互联网，也不加载目录中的技能。`tools.toml`、自动 `SKILL.md` 加载、
MCP 和动态插件均不是当前可用入口。

第一份研究能力包先采用**显式选择的方法说明 + 本地脚本 + 解析/fixture**：

- 方法说明给出适用目标、输入、前置条件、结束条件和输出解释，不创建新任务。
- 脚本仍通过现有 argv 工具执行；执行、超时、Job、资源冲突、原始输出、Receipt、
  Session、恢复、预算和审计只由内核原有路径管理，包不自带 AgentLoop。
- 如需结构化结果，复用已有 ObservationEnvelope/Research 写入边界；解析结果不是
  已确认漏洞，不能绕过 Artifact/Receipt/目标版本及证据关系校验。
- 方法说明可经显式 Project Prompt 文件提供；脚本可用现有读文件/命令工具调用。
  不保证目录中的说明自动进入上下文；不能把多份规则自动拼成长提示词。
- 包应可识别版本、来源、输入输出及回归样例。现有记录不足以重建包的某次输入时，
  明确记录缺口，再为实际需求设计最小绑定；不声称已经存在完整包版本/Resume 契约。
- 只有重复实际需求和测量证明通用工具不足，才评估专用注册工具或加载配置。
  暂不新增 manifest 标准、安装器、热加载、动态 Rust ABI、Hook registry 或工作流 DSL。

“可插拔”是研究方法可替换、数据契约可复用，不是现在就开发插件平台。
新扩展不得凭自身说明覆盖当前任务、自动扩大目标范围或将派生结果提升为证据。

## 5. 验收与下一步顺序

| 场景 | 离线验收可证明 | 后续真实模型验收需观察 |
|---|---|---|
| 旧 Project + 新 Session + hello | 当前输入/背景/Phase 的请求内容、顺序与来源 | 不主动读旧目标或启动研究 |
| 只检查连接并停止 | 约束送达、工具结果真实留存 | 足够证据后停止，不接续旧目标 |
| 更换目标、明确/歧义“继续” | 新输入进入既有 Turn，历史未被改写 | 正确承接或澄清、不跨目标套用结论 |
| Compaction/Resume 后纠偏 | 当前显式规则保留、引用/配对/审计正确 | 不把历史摘要重新当执行指令 |
| 后台 Job 中停止/纠偏 | 已有取消/租约/发现/未知效果边界 | 正确使用生命周期工具、不虚称已回收 |
| 第一份普通工程能力包 | 脚本/输出/Observation 沿既有执行链 | 方法可替换且未触发无关探索 |

复用现有 `tests/m4_research_control.rs`、`tests/request_audit.rs` 和
`tests/cli_chat_cases/{operator_steering,current_fact_guidance,environment_guidance}.rs`。
Mock 返回一条问候不能证明模型不调用工具；新增断言要验证实际请求，不以脚本答案冒充质量。

推荐依次单独授权：

1. 最小 Phase/当前任务措辞修复：沿用 Prompt 版本机制，保留历史字节和原预算压力门；测试新 Session、
   旧项目及 Resume 的真实请求组合。若固定资源语义变化，先新增对应 ADR/增量版本。
2. 完成现有超时测试框架诊断缺口，超时前保留有界 stdout/stderr/退出状态，不能吞掉首轮失败。
3. 每个实施 Slice 完成专项测试 → 受影响测试 → 独立审计 → 修复 → 完整 Gate → Lean 后，
   再单独授权有请求数/时间上限的普通工程 Live，
   固定背景与问题，区分请求正确性和模型服从性；不使用漏洞题目替代这项验证。
4. 依据测量再确定上下文表达的必要最小修复与首个能力包，不同步铺开插件/RAG/内核重构。

稳定内核候选还需覆盖纠偏、参数纠正、压缩/恢复的组合、失败诊断，以及新旧事件/二进制
兼容和回退边界。540 项离线通过不等于真实模型稳定；旧二进制不能读取 F3 新拒绝事件，
回退不能以旧程序直接恢复这些 Session。本契约不宣布内核封存。
