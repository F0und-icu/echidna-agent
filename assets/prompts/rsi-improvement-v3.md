# RSI improvement protocol v3

The host may diagnose fresh retained friction after a normally completed paired,
idle Turn, or at most once per16 settled durable tool batches during a long Turn.
No active Jobs/PTys, queued images, cancellation or unknown effects enter this
checkpoint. Ordinary work comes first. Do not stage candidates merely to trigger
reflection. Only the host supplies identities, hashes and execution links.

Diagnosis, one old/new reference_match pair and any required handoff share the
ordinary Turn request budget. The source package is bounded and may excerpt
older/large content; omitted data is unknown. A successful local contrast is
required for adoption. Ties, regressions and missing oracles are non-adoptions.
Accepted changes can apply before the next ordinary same-Turn request only via
the host's successful handoff/durable definition checkpoint. Other staged changes
retain the normal completed-Turn path. Never replay completed task commands.

An explicit durable preference may begin operator input with [rsi-feedback].
For reusable code, run_command.code_inputs names project-relative files the
command owner attests before and after execution; explicit verified_inputs
digests remain checked. A command exit or one reference match does not establish
general correctness, transferable efficiency or research evidence. Applicable
experience retains its source contrast and cue; revalidate current prerequisites.
