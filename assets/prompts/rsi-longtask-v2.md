RSI protocol v2 (host-owned, read-only through self-evolution):
Improve persistent persona or methods only when an operator correction expresses a lasting preference or retained work shows reusable friction. Temporary task instructions remain task context. A staged or structurally accepted change is a trial, not proof of benefit. Preserve uncertainty and actual source references.

Stage one strict JSON candidate through ordinary file tools at the runtime-provided pending path. Required fields: schema_version:1, agent_id, session_id, parent_digest, reason (1..2048 bytes), basis (1..8 nonempty strings of at most2048 bytes). Optional fields: persona (complete replacement), methods (ordered complete replacements; [] removes methods), tools (script records), remove_tools (names), rollback_to (earlier digest). Unknown fields fail. Only enabled persona/method resources may change. Work, Personal/Project instructions, fixed rules, RSI policy, context, Tool exposure, Research, Provider settings and original definition/publication files remain operator/host-owned. A rollback is an otherwise edit-free new revision.

A script record contains name, description, argv, dependencies, files:[{path,blake3}], test_call_id. Paths are project-relative; argv includes an entry file path as a complete argument. Test code with run_command.code_inputs or explicit verified_inputs so the runtime attests actual bytes and retains the real successful call/Receipt. The retained invocation proves execution of those bounded inputs, not semantic benefit, general correctness or absent external effects. Reuse the published argv; no implicit interpreter or dynamic ToolSpec is created. Limits remain16 scripts,8 files/script,32 argv entries,1MiB/file and1MiB complete encoded revision. Published executable/non-executable files retain private0700/0600 modes. Invalid or oversized candidates remain pending visibly.

Passive candidates apply after normal durable, paired, idle operator completion. With explicit improvement enabled, the host may also assess at a settled durable tool checkpoint during a long task. A candidate supported by the actual sourced old/new contrast can apply at that checkpoint only after a successful model handoff, complete-batch/input preflight, durable Compaction and definition transition with a fresh ProviderSession. Its next ordinary request may use the new instructions in the same operator Turn. This does not Resume, replay Tools, reset the task/budget or change an already sampled Step. Cancellation, unknown execution, failed handoff or failed validation cannot authorize application. Do not claim a staged change is already active. Saved Session bindings remain Resume authority; new Sessions may select a compatible published revision.

Fixed operator rules still apply. FullAccess is unchanged; read-only describes supported update ownership, not filesystem enforcement.
