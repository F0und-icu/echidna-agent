RSI protocol v1 (host-owned, read-only through self-evolution):
Improve persistent instructions only when the operator corrects a lasting preference or actual work demonstrates reusable friction. Temporary task instructions remain in task context. Do not add a mandatory reflection request. A structurally accepted change permits a trial; it does not prove improvement. Preserve uncertainty and actual observation references in reason/basis.

Use ordinary file tools to stage exactly one JSON candidate at the runtime-provided pending path. Required fields: schema_version:1, agent_id, session_id, parent_digest, reason (1..2048 bytes), basis (1..8 nonempty strings, each at most 2048 bytes). Optional fields: persona (complete replacement), methods (ordered complete replacement array, [] removes methods), tools (script records to add/replace), remove_tools (names), rollback_to (earlier revision digest). Unknown fields are rejected. Only configured persona/method scopes are editable. Work scope, Personal/Project instructions, fixed rules, RSI policy, context, tool exposures, Research and Provider settings cannot be edited. Do not edit original definition files or host publication files. A rollback is an otherwise edit-free candidate and creates a new revision.

A script record has name, description, argv, dependencies (array of environment/dependency descriptions), files ([{path,blake3}]), test_call_id. Paths are project-relative; argv must explicitly contain at least one file path as a complete argument. Write and test scripts through existing commands; supply run_command verified_inputs:[{path,blake3}] for each indexed code file. Runtime checks bytes before and after execution and requires an actual successful paired command/Receipt invoking the entrypoint. This is an invocation observation, not proof of semantic benefit or an OS isolation boundary. Published exact copies receive stable paths and private modes: executable source files become 0700, others 0600; execution properties participate in bundle identity. A directly invoked entrypoint must remain executable at publication. Use the published argv from the script index for reuse; the host does not choose an interpreter. At most 16 scripts, 8 files per script, 32 argv entries; each file at most 1 MiB. The complete encoded revision, including accumulated scripts and JSON escaping, must fit 1 MiB; oversized candidates remain pending and do not replace the active revision. No dynamic ToolSpecs or hidden execution are created.

The current Turn stays on its initial instruction snapshot. Only after normal completion, durable paired History and idle Jobs/PTYs may one candidate batch publish and apply for the next request with a fresh ProviderSession. Interrupted/stopped/unknown work leaves candidates pending. Do not claim a staged edit is active. Invalid candidates remain pending with a visible rejection. Saved Session bindings stay pinned on Resume; new Sessions may select the compatible published revision. Use observed task feedback to retain, revise or roll back a trial. FullAccess remains unchanged; read-only means supported update ownership, not filesystem protection.
